# AGENTS.md — Working on tradbot with an AI coding agent

Canonical guidance for ANY AI coding agent (Devin, Windsurf, Codex, Grok, Claude, …) and useful for humans too. CLAUDE.md is just a pointer here. Keep this file tool-agnostic.

## What this repo is

A multi-LLM consensus crypto trading bot that places **real-money orders on Coinbase** (plus DEX experiments). Several people run it against their **own** Coinbase accounts and API keys. Treat every change to order placement, consensus/vote logic, parsing of LLM output, or spend limits as a **money-path change**: it needs tests, and it needs to be called out plainly in reports and commit messages.

## Hard rules

1. **Never place a trade or run live mode.** Live runs are for the repo owner only (they require `--live` AND `LIVE_TRADING_CONFIRMED=1` — an anti-accident interlock, not a suggestion). Read-only exchange calls (`get_accounts`, `list_orders`, `get_fills`, product/candle data) are fine.
2. **Any bot run you make must be `--trading-mode=whatif` AND redirect history**: set `HISTORY_DIR=<scratch dir outside the repo>` so `history/` (real per-user data) is never touched. Verify with an md5/mtime check if you ran anything.
3. **Never commit per-user data**: everything under `history/` (recommendations, executions ledger, backups), `live_trades/`, `.env`, `cdp_api_key.json`. The `.gitignore` enforces this — don't fight it, and don't "fix" it by force-adding.

   **Accepted, do not rewrite history:** pre-cleanup per-user data (`history/recommendations.json`, `live_trades/` files, `history/llm_compare_history.json`) already lives in the *shared remote* git history — every commit that added it is on `origin/main`, and the only local commit touching those paths *removes* tracking. Treat pulled-down shared history as intentionally preserved: **NEVER rewrite git history** (filter-repo/BFG) to purge it. Forward protection is the `history/*` gitignore allowlist + `check_staged_hygiene.sh`, not a history purge.
4. **Don't commit unless the owner asked.** House style: make verified progress, leave changes uncommitted, propose a small set of consolidated commits at review checkpoints. Money-path changes stay separable from infrastructure when commits happen.
5. **Model IDs live only in `modelregistry.py`** (env overrides: `GEMINI_MODEL`, `CLAUDE_MODEL`, `OPENAI_MODEL`, `GROK_MODEL`, `PERPLEXITY_MODEL`). Never hardcode a model string elsewhere. Provider IDs rot fast (grok-4 died within weeks of being current); when in doubt run the preflight (below) or check `MODELS.md`.
6. **Small paid LLM probes are pre-authorized** by the owner for verifying model validity and call/response shapes (keep it to cents). Exchange **writes** are never authorized.

## Environment

- Use `./venv/bin/python` (3.11). The system `python3` (3.9) lacks every dependency and will fail at `from google import genai`. A fresh environment needs `pip install -r requirements.txt -r requirements_dev.txt` — pytest lives in `requirements_dev.txt`, so the verify step below fails without it. A bare `pytest`/`python3 -m pytest` that hangs or times out during *collection* is this mistake, not a heavy suite — `./venv/bin/pytest -q` collects ~800 tests in ~3s; treat any "collection hangs" conclusion as wrong-interpreter until proven otherwise.
- Keys come from `.env` (loaded via python-dotenv). Coinbase needs `cdp_api_key.json` at repo root — required even for what-if runs (client is constructed either way).
- `import crypto_trading_bot` is **side-effect-free** (no argv parsing, no network, no client construction — all of that happens in `main()`). Keep it that way; tests depend on it. If you add module-level code that touches network/env/argv, you've broken the repo's testability.
- **Timestamp contract (load-bearing):** history records, ledger rows, and LP files store naive-UTC timestamps with a literal `'Z'` suffix (`isoformat()` without offset + `'Z'`); `tradeanalyzer.parse_timestamp` and the LP parsers depend on this exact shape, and regression tests pin it. Do not switch any storage site to aware `isoformat()` (which appends `+00:00`) piecemeal — going timezone-aware end-to-end is a planned dedicated migration. Never compute epoch time via `.timestamp()` on a naive datetime (it assumes *local* time — this was a real 4-hour bug in `lp_history.py`, then recurred in `tradeanalyzer.py` and was fixed 2026-07-19); use `datetime.now(timezone.utc)`, and convert stored naive-UTC datetimes to epoch only via `tradeanalyzer.utc_epoch` (the named, tested conversion helper) — a bare `.timestamp()` on a stored datetime is a bug on sight.
- **`history/` mixes per-user data (gitignored) with code**: `history/recorder.py` is source and `history/test_expected_output.csv` is a documented fixture, both tracked. If a task says "don't touch history/" it means the *data*; if it says "migrate all code" that includes `recorder.py` — ask or flag the conflict rather than guessing.
- **Env-snapshot convention:** `.env` loads in `main()` (not at import — import is side-effect-free, pinned by `tests/test_import_purity.py`), so module-level `X = os.environ.get(...)` snapshots in the bot's import graph are re-resolved by `crypto_trading_bot._refresh_env_snapshots()`. Adding or changing such a snapshot in any module the bot imports requires updating that function and the refresh test in the same change — or importing the module lazily inside a function.
- **Manual probe scripts are named `probe_*.py`, never `test_*.py`** — the `test_` prefix makes pytest collect them, and two probes hit live APIs/wallets (one formerly fired an authenticated Coinbase call at collection). `pytest.ini` scopes collection to `tests/` for the same reason; do not remove it as "boilerplate".
- **Feature extras are separate requirements files** (`requirements_correlation_tracker.txt`, `requirements_dex.txt`, `requirements_llm_compare.txt`) and are NOT pulled in by `requirements.txt`. Features degrade *gracefully* without them — e.g. the correlation tracker silently skips Granger causality when `statsmodels` is absent — so a "feature behaving oddly" diagnosis should start with "is its extras file installed?" (2026-07-19: the missing dep also exposed a crash in the skip path; graceful-degradation branches are the least-tested code in a feature).
- **macOS has no `timeout`/`gtimeout`** — `timeout 60 cmd` exits 127 and looks like the command failed. To bound a long-running CLI (e.g. a bot run you only need the startup banner from), run it in the background, poll its output file for the line you need, then kill it.
- **`load_dotenv()` resolves `.env` from the calling file's path, not cwd or env** — so `env -i` does NOT simulate "no keys" for repo-root scripts; the real `.env` still loads (and a careless test run makes real paid calls). To exercise no-key paths, move `.env` aside (verify byte-identical on restore) or monkeypatch `load_dotenv`. Both `crypto_trading_bot.py` and `llm_compare.py` (since 2026-07-19) load `.env` in `main()`; llm_compare's import graph was verified to have no import-time env snapshots, so it needs no `_refresh_env_snapshots` twin — re-verify that if its imports change.

## Preparing and executing commits (when the owner asks)

Hard rule #4 stands: don't commit unless the owner explicitly asked, in that session, in commit-words ("commit it", "execute the commit plan"). When they have, this is the procedure that worked (7-commit backlog landed cleanly 2026-07-19):

1. **Write commit plans file-partitioned.** Each file wholly in exactly one commit — never a plan that needs hunk-level staging. If source files span logical phases, group by file anyway and say so in the message. This is also how to write a handoff doc for a future committing session; put addenda in the doc itself and read them before staging (an addendum can move files between commits).
2. **Reconcile before staging anything**: `git status --porcelain -uall` (plain status collapses untracked directories and hides files), then check the partition — every dirty/untracked path in exactly one commit or on an explicit leave-alone list. Anything unaccounted for gets flagged to the owner, not guessed.
3. **Bracket with the suite**: `pytest tests/ -q` green before the first commit and after the last. After the last, also verify the working tree matches the plan's predicted end state (the plan should state one).
4. **Per commit**: stage, run `./scripts/check_staged_hygiene.sh`, read the staged diff yourself, then show the owner the file list + proposed message and wait for their yes. The script only pattern-matches; *you* judge context — e.g. a fixture carrying a real exchange `order_id`/fill details may be intentional, but flag it explicitly and let the owner decide.
5. **Message style**: imperative subject ≤ ~50 chars, body explains what and why, money-path changes called out plainly. **No authorship/attribution lines of any kind** (no `Co-Authored-By`, no "Generated with …") — owner's standing rule.
6. **Mechanics that bite**: flag-like filenames need the `--` separator (`git add -A -- './--use-fib'`); after `git rm --cached`, confirm the files still exist on disk *and* that `.gitignore` now covers them so they can't be re-added.
7. **Never push.** Committing authorization is not pushing authorization.
8. **Hygiene is not diff-only**: `.gitignore` never retroactively untracks — after tightening ignore rules, run `git ls-files <dir>` on every user-data dir (`history/`, `live_trades/`, `paper_trades/`) and `git check-ignore` the survivors; `history/llm_compare_history.json` sat tracked for a day after the allowlist landed (caught 2026-07-19, untracked via `git rm --cached`). Also `file`-check any oddly-named extensionless untracked entry before `git add` — a root file named `typescript` turned out to be an accidental `script(1)` terminal capture, not source.
9. **Audit deletions by inversion**: don't just verify that documented moves/removals happened — enumerate every `D` in `git status` and ask "does `docs/SUPERSEDED.md` account for this?" The gaps are always the deletions nobody thought worth recording; give even junk removals (empty files, pasted transcripts) a one-line entry so the next verifier doesn't burn a step distinguishing omission from intent.
10. **Trust only a fresh suite count.** Same-day docs legitimately carry different counts (723 → 790 → 798 across 2026-07-19 as sessions landed tests); when a doc states a count, stamp it with the command and date, and re-run before staging rather than reconciling stale numbers.

## Secrets scanning (optional)

This repo relies on `.gitignore`, `./scripts/check_staged_hygiene.sh` (run manually against the staged diff — see the commit procedure above), and code review to keep `.env`, `cdp_api_key.json`, and key material out of commits — there's no automated scanner installed. Nobody should install one on another contributor's behalf, but if you (the repo owner) want a local pre-commit guard, [gitleaks](https://github.com/gitleaks/gitleaks) via [pre-commit](https://pre-commit.com/) is a lightweight option. Add a `.pre-commit-config.yaml`:

```yaml
repos:
  - repo: https://github.com/gitleaks/gitleaks
    rev: v8.18.4  # pin to a current release when you install this
    hooks:
      - id: gitleaks
```

Then `pip install pre-commit && pre-commit install` once, locally, to enable it. Nothing here is installed or required by the codebase — this is a snippet for the owner to opt into, not a dependency.

## Architecture map (runtime path vs the rest)

- **Live bot runtime path**: `crypto_trading_bot.py` (main loop, consensus via `PanelDecision`, trade gate) → `marketdata.py` (Coinbase OHLCV + Fibonacci block, cached per coin, injected into every analysis prompt as the primary data section; Trends/CMC/SOCIAL are labeled secondaries inside it — CMC via `coinmarketcaputil.py`, SOCIAL via LunarCrush's `coins/v1` + `topic/v1`, both self-fetched by `build_market_block` so the existing per-coin-per-run cache covers them too) → `claudeutil.py` / `openaiutil.py` / `grokutil.py` / `perplexityutil.py` (panel traders; Gemini is called inline) → `voteschema.py` (schema-enforced JSON votes for all five panelists; grok/perplexity keep the hardened delimiter parser only as a loudly-logged fallback for when the provider rejects the schema parameter itself) → `coinbaseutil2.py` (orders, fill confirmation) → `historyutil.py` (recommendations) + `executionledger.py` (intent/fill rows, positions, daily cap).
- **Parallel stack**: `llm_utils/` + `config.py` + `prompts/` serve `llm_compare.py` only (a standalone tool). It duplicates the provider clients — a known wart; if you change provider behavior, check both stacks (the registry already covers both).
- **`PanelDecision` is action-only.** `resolve_structured_vote` returns just `vote.action`; confidence, reasons, and any future vote field never reach `PanelDecision` (`votes` is `{llm: action-string}`). Any feature that reasons over a per-panelist signal (edge estimates, confidence weighting, majority mode) must first plumb the `Vote` object into a new decision field — see `docs/design/EDGE_VS_FEE_GATING_FEATURE.md` for the worked example.
- **Gate boundaries in the buy path are load-bearing.** Decision-quality checks belong in `gate_and_maybe_buy` (shared, lock-free wiring used by both loops); spend caps stay in `maybe_execute_buy` (which holds the ledger lock from cap check through order placement). Read each function's docstring *rationale*, not just behavior, before inserting a new check. Note the live and whatif daily-cap branches are structurally different (live fails closed + quarantines; whatif soft-fails + continues) — an agent can only ever exercise the whatif branch, so demos/tests of cap refusal prove the same *shape*, not the same *code path*, as live. Related: `executionledger.live_spend_today()` and `spend_today(trading_mode=...)` are two separate entry points over the same `intended_spend_on_date` sum, not one function with a kwarg.
- **Coin-selection precedence** (fixed 2026-07-19): filters (`--chains`/`--categories`/`--polymarket-filter`) and `--discovery` only apply in discovery mode (empty coin list). `resolve_coin_selection_conflict` implements the decision table: env `ANALYZE_COINS` + CLI filter flag → env coins overridden with a loud `[CONFIG]` notice; CLI `--coins` + CLI filter flag → hard error; banner/summary print filter lines only when they actually apply. Residual accepted path: env coins + env filters (both in `.env`) — coins win silently, but the banner no longer advertises the inert filter. The DEX path auto-sets `CHAINS=['solana']` as a validation constraint even with explicit coins (own `[DEX]` notice, no banner filter line) — so `CHAINS` truthy does NOT imply an active coin filter. Subtlety: `os.environ['ANALYZE_COINS']` doubles as the traders' prompt-framing signal ("meme coin" vs "cryptocurrency", set early by `resolve_analyze_coins_env`); any late switch of coin-selection mode must reconcile the env var (`os.environ.pop`), not just the module global. Spec'd by `tests/test_filter_precedence.py`.
- **Tests**: `tests/` (pytest). Consensus and parser behavior are spec'd by tests — read `tests/test_consensus.py` before touching vote logic. The test suite is also the fastest recipe book for *faking* a state — e.g. `tests/test_run_summary.py`'s `buy_calls` fixture is the canonical way to force a BUY through `maybe_execute_buy()` with no LLM call; check for an existing fixture before inventing a harness.
- **Reference docs**: `MODELS.md` (model registry, migration history, per-provider request/response shape appendix — read before touching provider calls), `docs/RUNBOOK_live_acceptance.md` (owner-executed live test), `docs/RUNBOOK_whatif_cadence.md` (scheduled what-if runs — the analyzer's data engine), `EVALUATION_LESSONS_LEARNED_2026-07-18.md` (the empirical audit this architecture came from), `docs/reflections-2026-07-18/` (first-person implementer reflections + SYNTHESIS.md with the fix-candidate queue F1–F9/R1–R4), `docs/reflections-2026-07-19/SYNTHESIS.md` (the improvement-plan execution session: process lessons + the owner follow-up queue), `docs/audit-2026-07-19/` (full-repo audit with per-finding outcomes) + `docs/SUPERSEDED.md` (main→josh capability map).
- **Docs layout convention**: the repo root keeps only `README` / `AGENTS` / `CLAUDE` / `MODELS` / `OPERATIONS_MANUAL` (+ the two live `llm_compare` docs); `docs/design/` holds specs for unbuilt or superseded designs, `docs/archive/` holds historical plans, and `docs/` itself holds stamped records and runbooks. Date-stamped docs are frozen at that date — never update them for later renames/refactors (they intentionally keep old filenames); only living docs get link maintenance. Before any rename/removal, grep the whole repo (`*.py` **and** `*.md`, both branches: `git grep NAME origin/main -- '*.py' '*.md'`) for the old name — references ripple non-locally, including a renamed file's own docstring.

## Known API gotchas (all empirically verified — don't rediscover them)

- Coinbase create-order nests everything under `success_response`; fill details need a follow-up `get_order`. Numeric fields are **strings**. Fees: `total_fees` is populated, `fee` is often `''` (audit anything reading `fee`). Fees are ~1.2%/side at small notional (~2.4% round trip — measured).
- Coinbase `get_candles` takes unix-second **string** bounds and returns candles with string numeric fields, capped at ~300 rows/request — this bounds how far back a benchmark price can be fetched at hourly granularity.
- The execution ledger records only **BUY** fills today; round-trip fee estimates are 2× the entry fill's fee. SELL-side rows don't exist yet.
- **CMC symbol collision**: `/v3/cryptocurrency/quotes/latest` looked up by symbol returns a list; taking `data[0]` can be the **wrong asset** for obscure tickers. ID-based lookup via `coinmarketcaputil.SYMBOL_TO_CMC_ID`/`get_cmc_id` is the planned fix — those helpers are intentionally kept even while uncalled.
- The Coinbase SDK has **no server-side `client_order_id` filter**; duplicate-order recovery lists recent orders and matches client-side.
- **Duplicate `client_order_id` is NOT an error** (validated live 2026-07-19, runbook §7): resubmitting the same `client_order_id` returns `success: true` with the **original** `order_id` — idempotent dedupe, no error text, no second fill. Never string-match error text to detect duplicates (`_looks_like_duplicate` is log-annotation only and cannot fire on the real shape); the duplicate signal is the returned `order_id` matching the ledger's row for that `client_order_id`. Fixture: `tests/fixtures/coinbase/duplicate_rejection.json`.
- **LLM self-correction debris can survive into parsed `reasons`** even when the typed vote fields (action/confidence/abstain/symbol) parse cleanly — observed live from Claude (fragments like `"]}...__ERROR__ retrying:{"` and a stray literal `"abstain"` as reasons). Root cause: `voteschema.parse_vote` validates reasons by *type* only (voteschema.py:226-231), no content checks. Blast radius is stdout/logs only — history records store action strings, never reasons (`resolve_structured_vote` returns just `vote.action`). FIXED 2026-07-19: `parse_vote` now decodes the first complete JSON object only and content-filters reasons (majority-debris fails closed as `reasons content corrupt` → `abstain('parse_failure')`); spec'd by the content-hygiene tests in `tests/test_voteschema.py` and the malformed-stream regression in `tests/test_structured_requests.py`. Reasons remain display-only text — never trade on them.
- GPT-5.5 and Gemini 3.1 are reasoning models: small `max_tokens` budgets get consumed by reasoning and return **empty visible text** with `finish_reason=length`/`MAX_TOKENS`. Give generous output budgets; treat empty-text-at-cap as an abstain/parse-failure, never as consent.
- Grok's `max_output_tokens` is a soft cap (observed exceeding it). GPT-5.x wants `max_completion_tokens` (not `max_tokens`) and rejects `temperature`.
- Google Trends (pytrends) 429s frequently and its series are scaled max=100 per window — an all-zero series with one blip looks like a "spike to 100". Don't treat it as decision-grade data.
- Structured-output quirks (probed live 2026-07-18, re-probed 2026-07-19, fixtures in `tests/fixtures/structured_output/`): Claude's json_schema output_config **rejects `minimum`/`maximum`** on numbers (enforce bounds client-side); Gemini's `response_schema` **rejects `additionalProperties`** but **coexists with google_search grounding**; OpenAI accepts full strict schemas; Perplexity **returns unterminated JSON when it hits max_tokens** — never trust an unparsed tail (fail closed to abstain(parse_failure)). All five providers are now on native structured output. Grok's Responses API `text.format` json_schema is **adopted** (T8 phase 2, 2026-07-19): the re-probe confirmed it **coexists with the `web_search` grounding tool** in one request (the earlier "unadopted" note is superseded). Grok and Perplexity keep the delimiter-tag parser only as a fallback used ONLY when the provider rejects the schema *parameter* itself — a structured attempt that returns garbage abstains, it is never re-parsed as a tag.
- **CoinMarketCap** (`COINMARKETCAP_API_KEY`, Free tier, 15k credits/mo, 50 req/min): `/v3/cryptocurrency/quotes/latest` (1 credit) and `/v1/cryptocurrency/map` (0 credits) verified current. Adds rank/dominance/supply/multi-window % changes that candles don't have. `coinmarketcaputil.py` has its own client-side throttle; `marketdata.py`'s CMC section (T12) reuses it.
- **LunarCrush** (`LUNARCRUSH_API_KEY`, Individual plan since 2026-07-18: 10 req/min, 2,000 req/day): WORKING (the earlier free-tier 402 wall is gone). Two verified endpoints: `/api4/public/coins/:SYMBOL/v1` (galaxy_score, alt_rank, market_cap_rank, price, volatility, percent_change_24h/7d/30d — no sentiment here) and `/api4/public/topic/:topic/v1` (topic slug = lowercased coin *name*, e.g. `bitcoin` not `BTC`; interactions_24h, num_contributors, num_posts, per-network `types_sentiment`). Auth is `Authorization: Bearer <key>` **plus a real `User-Agent` header — Python's default UA gets Cloudflare 403 "error code: 1010"**, which looks like an auth failure but isn't. Individual plan excludes topic time-series and `/coins/list/v2` (Builder+ only). `marketdata.py`'s SOCIAL section (T13) makes both calls per coin per run and derives an aggregate sentiment score as an interaction-weighted mean of `types_sentiment` (a judgment call — see marketdata.py's `_aggregate_sentiment` docstring).

## Process lessons that keep this repo workable

- **Write the spec as failing tests first** (xfail), then implement until they flip. The consensus hardening was delivered this way; it works.
- **Serialize work that touches `crypto_trading_bot.py`** — it's one big file and every behavior change lands there. Parallel edits to it will conflict. (Splitting it into modules is the standing refactor candidate.)
- **Report judgment calls explicitly.** When you make a choice the task didn't specify (a default, a fallback, a classification), list it in your summary — the owner reviews those.
- **Fail closed on the money path.** An error, refusal, missing panelist, or unparseable vote must block a trade, never shrink the quorum or fall back to a single model. This is the repo's core safety invariant — regressions here are the worst class of bug. Fail-closed means closed against the input's whole *type domain*, not just exceptions: valid-but-wrong-shape data (a `{}` ledger, a list where a dict belongs) and falsy-but-non-None values (`''` order ids) are corruption too — when loading any money file, validate shape, not just parseability (both classes were real review findings 2026-07-19). Corollary: when a money-path change *loosens* anything (frees budget, unblocks a path, dedupes a sum), call that direction out explicitly in your report — the fail-open hunt starts there.
- **Label data honestly.** History records carry `trading_mode` (`live`/`whatif`/`unknown`); `unknown` means "could not verify", never guess. Simulated data must never be indistinguishable from real.
- **Probe before you migrate.** For any provider-API change, make tiny live calls first and save the request/response as fixtures — every provider had an undocumented quirk that would have been a runtime bug (see gotchas above). A valid key is not proof of data access (LunarCrush 402s everything); verify the data surface, not just auth. Corollary (2026-07-19): when a fixture or doc says a capability is "unadopted"/blocked, read *why* — if the reason is an unverified open question, a cents-scale re-probe often flips it (Grok's schema+web_search coexistence was assumed incompatible for a day on no evidence).
- **When a call can produce output via more than one path, tag the path on the response object — never infer it from the content bytes.** The structured-vote migration carries `vote_path` on the response so garbage from a structured attempt abstains instead of being re-parsed as a delimiter tag. Content-sniffing the path is the phantom-BUY bug class that spent real money.
- **Investigate the existing flag before inventing one.** `--log-rounds` already gated exactly the panel-response dumps; the verbosity fix re-aimed its destination rather than adding a switch. Trap: there are TWO `--log-rounds` definitions — crypto_trading_bot.py (default true, gates panel dumps) and config.py/llm_compare (default false, different entrypoint). Grep both before reasoning about "the" flag.
- **Inject at seams, not through the money path.** New data/features should reach prompts via caches/wrappers around the consensus code, not new parameters threaded through it — `marketdata.py`'s block cache added a whole data pipeline with zero changes to `process_coin_with_comparison` or its tests.
- **Supplied data fixed the HOLD problem.** The eval's "frontier models refuse/HOLD by default" was a data-starvation artifact, demonstrated live: with a real market block, all panelists analyze and disagreements become analytical (that's the disagreement the consensus gate exists for). If models start refusing again, check what data the prompts carry before touching models or prompts.
- **The adversarial-data surface is an accepted, bounded design — not an oversight.** grok and perplexity run live web search *inside* the voting panel and discovery proposes tickers from public content, so a coordinated pump/astroturf campaign can, by design, steer votes toward a listed meme coin; round-2 peer analysis then embeds raw peer-LLM text (which may itself carry web content) into the other models' prompts. It is bounded, not open: votes are schema-constrained and symbol-bound, so injected text can influence a model's *reasoning* but can never forge a vote. The backstops are independent multi-model consensus, Coinbase listing validation, and the spend caps (defaults: $5 per-order notional, $10 per-run, $15 per UTC day — all configurable via flags/env). Don't "fix" this by stripping free text out of the panel — it's a documented acceptance of a residual risk the caps and consensus bound.
- **Verify spec claims against the code before destructive action.** Task specs inherit errors (a "delete `--use-fib` flag" instruction actually meant a junk *file*; the live flag was an unrelated documented feature). The spec tells you where to look; the code tells you what's true. Corollary: "zero callers" and "not intended API" are different facts — check both before deleting a helper.
- **In multi-agent work, the invariant is a file-ownership list, not a global test count.** Parallel agents in one tree each saw the suite grow from the other's files and burned time proving the delta wasn't their bug. Give each agent an explicit list of files it owns; "files outside your list unchanged" is checkable, "N tests" is not.
- **Harvest reflections from implementing agents at phase ends.** Final reports systematically omit near-misses and design doubts; asking each agent afterward for a first-person reflection surfaced three money-path risks no report contained (see `docs/reflections-2026-07-18/SYNTHESIS.md`). Completed agents can be resumed from their transcripts for this even after the orchestrator's context is compacted.
- **All panel analysis prompt text lives in `panelprompts.py`** (single source since 2026-07-19; per-provider drift quirks are cataloged in its module docstring and pinned byte-for-byte by `tests/test_panel_prompts.py`). Changing any prompt requires regenerating `tests/fixtures/panel_prompts/golden_prompts.json` (one-liner in the test file's docstring) in the same commit, called out as a prompt change; never edit the fixture by hand, and never "normalize" a whitespace quirk mid-refactor — that's a semantic prompt change needing its own reviewed commit. A new provider gets its prompts from the builders (explicit preamble/vote-instruction kwargs) plus golden cases — no inline prompt strings.
- **Ledger locking contract:** the execution ledger and recommendations history each have a sibling `.lock` (flock, reentrant per-thread, path resolved at call time so `HISTORY_DIR` redirects work); `maybe_execute_buy` holds the ledger lock from the daily-cap check through the intent write *including live order placement* (overlapping runs serialize buys); the two locks are never held together — a call path nesting `record_recommendation` inside the buy span is a deadlock bug.
- **`block_reason` vocabulary is spec'd by `tests/test_consensus.py`** — there is no separate enum/doc; read the test assertions before emitting or parsing block reasons.
- **Owner-run live acceptance is a distinct test layer** — 2026-07-19's session (results: `docs/ACCEPTANCE_RESULTS_2026-07-19.md`) falsified a documented API expectation (§7 duplicate shape) and surfaced two bugs (reasons junk, cap-tally undercount) that 599 passing tests never touched. When a runbook prediction is cheaply testable against the real API, test it and save the fixture; and read raw LLM output during acceptance, not just parsed verdicts.
- **Test-authoring traps (each cost real debugging time):** never `monkeypatch.setattr` an attribute on a real stdlib module (e.g. `time.time`) — modules are process-global singletons and you'll freeze pytest itself; rebind the *importing module's* name (`monkeypatch.setattr(mymod, 'time', stub)`) instead. Any new test that reaches `marketdata.build_market_block` needs the CMC/SOCIAL fetch stubs (see `tests/test_market_data.py`'s file-local autouse fixture) or it will trip the conftest network guard after slow real retries. `tests/conftest.py` blocks all sockets; `@pytest.mark.allow_network` is the explicit opt-out. Never call `monkeypatch.undo()` — fixtures redirect the money-record paths (`EXECUTIONS_FILE` etc.) via the same monkeypatch object, and `.undo()` re-points module state at the **real** `history/` mid-test (a test assertion once printed a real live order_id this way); use `pytest.MonkeyPatch.context()` for nested patches, and treat any realistic-looking order_id/run_id you didn't fabricate in test output as a stop-everything signal. When guarding against network at import, patch socket *methods* (`connect`/`create_connection`/`getaddrinfo`), never replace the `socket.socket` class — that breaks `ssl`'s import and fabricates false findings. Network-touching classes marked `pragma: no cover` are still testable: construct via `Cls.__new__(Cls)` to skip the credential-touching `__init__`, set the needed attrs, and stub the fetch boundary (see `tests/test_analyzer.py`'s provider tests). Importing a production class whose name starts with `Test` into a test module (e.g. `correlation_tracker.TestResult`) makes pytest try to collect it — alias it on import (`TestResult as TrackerTestResult`). Config globals like `RUN_ID`/`LOG_INTEGRATION_ROUNDS` are assigned only inside `main()`, not at module level — a helper that reads them must use `globals().get('RUN_ID')` (and tests fabricate them with `monkeypatch.setattr(..., raising=False)`), or it NameErrors when called outside a full bot run. Never write a test that asserts on the state of the repo's REAL `history/` paths (existence included) — the owner's legitimate runs create files there, so such a test fails forever the first time the feature is actually used (an import-purity test asserting `history/panel_responses` didn't exist broke the evening the feature shipped, 2026-07-19); run purity subprocesses from an empty tmp cwd instead.
- **Never `git stash` here.** The repo routinely carries a large pile of uncommitted tracked changes plus untracked test files that pair with them; a stash (without `-u`) reverts the tracked half and leaves the untracked half importing symbols that no longer exist — a fake `ImportError` that looks like your bug (cost real time 2026-07-19). Isolate your own changes with `pytest --ignore=<your new file>` instead.
- **Operator visibility must print before the analysis loop.** A HOLD/SELL vote short-circuits every downstream gate (spend caps, ledger, order path), so anything the operator needs to see *regardless of the vote* — cap state, mode, run id — belongs in the startup banner, not in the buy path (learned from the daily-cap line, 2026-07-19: a supervised live run gave zero cap visibility because the vote was HOLD).
- **Banner honesty: never print a config as active unless it will actually apply this run.** The 2026-07-19 filter-precedence bug was two bugs in one — filters silently ignored AND the banner advertising them as active; the second made the first invisible for a full day of runs. When wiring a new flag, gate its banner/summary line on the same condition that gates its effect.
- **Triage external reviews against the current tree before dispatching fixes.** A capable outside review of the 2026-07-19 live logs listed five "missing" controls; three already existed (benchmark analyzer, no-order reason lines, seeded cap tests) and only two were real gaps. Verify each claim in code first — agent-hours are better spent on the confirmed subset, and the confirmed subset was still gold (the filter-precedence catch).
- **When a spec offers "silently reinterpret conflicting inputs" as an option on a money path, reject it.** Conflicts either error out or override loudly with provenance stated; `get_config_source`'s CLI-vs-env distinction is the machinery that makes an override principled rather than a guess.
- **Modification specs need a different shape than greenfield specs.** `docs/design/` templates are greenfield-subsystem shaped (full dataclasses, CLI tables); a spec for a surgical change to the existing money path wants an insertion-point diagram, candidate-rejection arguments, and a test plan mapped to existing test files (see `EDGE_VS_FEE_GATING_FEATURE.md`).
- **When fixing a print/format bug, grep for the format string repo-wide first** — `correlation_tracker.py` carried two byte-identical inline copies of its 30-line report printer, and fixing one would have left the same crash in the other (2026-07-19; now a shared helper).
