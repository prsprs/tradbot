# Reflection — WS3 schema-v2 persistence agent (Opus 4.8), 2026-07-21

First-person reflection, collected post-implementation per the reflection-harvest practice.

---

I nearly threaded confidence back through `resolve_vote` — adding a second return value so the decision path carried the Vote object. That would have touched the exact contract AGENTS.md warns about ("PanelDecision is action-only ... any feature that reasons over a per-panelist signal must first plumb the Vote object") and rippled into every consensus test. What stopped me was the "inject at seams, not through the money path" rule plus the spec's "persistence only, do not change decision LOGIC": re-parsing the already-in-memory response with a side-effect-free `_vote_confidence` keeps the vote tally byte-for-byte identical, and the 826 baseline tests staying green confirmed I hadn't perturbed a single decision.

The hard part of the monolith wasn't any one function — it was that `process_coin_with_comparison` has ~7 distinct `PanelDecision` return sites (single-LLM action/abstain/init-failure, and `decide()`'s blocked/unanimous/tiebreaker, plus the no-coin/unknown-mode/exception blocks). Getting `vote_details` onto *all* the panel-bearing ones without missing a branch meant enumerating every return by hand; a grep-after was the only way I trusted I'd covered them. The confidence-merge for integrate mode (`{**r1, **r2}` so a re-queried panelist's Round-2 confidence wins but a carried Round-1 abstainer keeps its value) was the subtlest spot and I'd want a reviewer to re-check it.

A near-miss on the market-block file: my first instinct was to key the directory off `historyutil.HISTORY_DIR` (the import-time snapshot), which the panel-log path already does. But the recommendations writer keys off `RECOMMENDATIONS_FILE`, and the tests monkeypatch *that*. Deriving the dir from `RECOMMENDATIONS_FILE` instead made HISTORY_DIR redirection and test isolation both work; the AGENTS.md note about never asserting on the real `history/` is what pushed me to check which knob the tests actually turn.

Highest-leverage repo change for the next agent: the record schema is defined implicitly by keyword args threaded through two functions and read via `rec.get()` scattered across the analyzer — there is no single declaration of "what a v2 record is." A `RECORD_SCHEMA.md` (or a typed dataclass/`TypedDict` the writer and analyzer both reference) would turn "did I stamp every field on every path?" from a grep exercise into a type check, and would give the next person the field inventory I had to reconstruct from three files.

Two judgment calls the owner should weigh. (1) `prompt_hash` hashes only the *primary's* default coin-check prompt bytes — for grok/perplexity primaries (which add a preamble) it's a coin+data+template identity, not the literal prompt sent; if reproducibility needs to distinguish per-provider prompt variants, this is under-specified and should hash per-panelist. (2) `models` includes a panelist whose client failed to initialize, recording the model it *would* have used rather than one that ran — convenient for grouping but arguably dishonest against AGENTS.md's "label data honestly" principle; I'd accept a reviewer decision to drop init-failed panelists from `models` (they're still visible as abstains in `vote_details`). Neither affects gating; both are cosmetic-to-analytics, which is why I shipped them and flagged rather than blocked.
