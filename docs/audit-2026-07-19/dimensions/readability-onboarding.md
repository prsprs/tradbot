# Human readability & ease of use (newcomer experience)

## Summary
The core money-path code (PanelDecision, decision_allows_trade, the --help output) is genuinely well-commented and easy to follow once you find it, and error handling for missing LLM keys degrades gracefully with clear warnings. But the newcomer's actual first hour is rough: the README Quick Start literally fails on this machine's clean shell (no venv step, a dead env var), the real Coinbase-credentials requirement is contradicted by .env.example, and a first successful run silently writes into a directory shared with other users' real trading data with zero warning. Code-reading friction is secondary but real: no module docstring, no diagram, main() buried after ~40 helper functions in a 2629-line file.

## Strengths
- crypto_trading_bot.py --help is genuinely good: every flag's default is stated inline, and the two safety flags (--trading-mode, --live) embed the full double-lock explanation directly in --help text, so a user never has to read source to understand the live/whatif story (crypto_trading_bot.py:70-93).
- The trade gate itself is a model of readable money-path code: decision_allows_trade (crypto_trading_bot.py:1117-1142) is ~10 lines, has an explicit truth table in its docstring, and cites the specific historical bug each branch guards against; PanelDecision's docstring (crypto_trading_bot.py:1058-1079) enumerates every abstain reason code up front.
- Missing LLM API keys fail gracefully, not with a traceback: each of the 5 provider client constructions is individually try/except-wrapped with a plain-English 'Warning: Could not initialize X client: <e>' message and a registered standing abstain, consistent with the repo's fail-closed invariant (crypto_trading_bot.py:2166-2211).
- AGENTS.md itself is an excellent single canonical reference once a reader finds it -- thorough, empirically grounded, and honest about known warts -- and OPERATIONS_MANUAL.md correctly documents cdp_api_key.json and HISTORY_DIR (OPERATIONS_MANUAL.md:181-182, 269-284) that the top-level README Quick Start omits.

## Findings

### [HIGH/S] README Quick Start's literal commands fail on a clean shell -- no venv step, and system python3 lacks every dependency
**Evidence:** README.md:22-32 tells a newcomer to run `pip install -r requirements.txt` then `python crypto_trading_bot.py --llm-mode compare` with no venv setup at all. On this machine: `which python` -> not found, `which pip` -> not found (only python3/pip3 exist), and system `/usr/bin/python3 --version` is 3.9.6. Running `/usr/bin/python3 -c "from google import genai"` reproduces exactly the failure AGENTS.md:20 already warns about: `ModuleNotFoundError: No module named 'google'`. AGENTS.md:20 states this plainly ('Use ./venv/bin/python (3.11). The system python3 (3.9) lacks every dependency') but that guidance never made it into README's Quick Start, the section a newcomer actually follows.

**Impact:** A newcomer copy-pasting the Quick Start verbatim gets `command not found: python` or, if they substitute python3, a bare ModuleNotFoundError traceback with no indication that a venv is required -- the very first two lines of the onboarding path fail.

**Recommendation:** Rewrite README.md's Quick Start block to create/activate a venv first (`python3 -m venv venv && source venv/bin/activate && pip install -r requirements.txt`) and use `./venv/bin/python crypto_trading_bot.py ...` for the run command, matching what AGENTS.md and OPERATIONS_MANUAL.md already tell agents to do.

### [HIGH/S] Quick Start's `export COINBASE_API_KEY=...` is a dead variable; the real requirement (cdp_api_key.json, needed even for what-if) is undocumented there and contradicted by .env.example
**Evidence:** README.md:28 tells the user to `export COINBASE_API_KEY=...`. Grepping the entire codebase (`grep -rn COINBASE_API_KEY --include=*.py .`) shows this variable is read nowhere -- the actual mechanism is a JSON file, `cdp_api_key.json` (or `COINBASE_CREDENTIALS_FILE` override), read in coinbaseutil2.py:118-120. Worse, crypto_trading_bot.py:2264 constructs `trader = BlobbyTrader()` unconditionally whenever `--dex` is not passed (the `else` branch of `if DEX_MODE:` at line 2245), with no WHATIF_MODE check, so even a default what-if run needs this file. .env.example:30 says the opposite: `# --- Trading (required for live trading only) ---`. README.md:204 (the API Integrations table, far below the Quick Start) actually has the correct statement ('Always ... client is constructed even in what-if mode') -- the README contradicts itself between its top and bottom. AGENTS.md:21 already documents 'cdp_api_key.json ... required even for what-if runs' as a known fact -- this finding is that the human-facing README/.env.example were never updated to match.

**Impact:** A newcomer follows the Quick Start, sets a key that does nothing, skips the file that's actually required, and their first run raises an uncaught `FileNotFoundError` traceback from coinbaseutil2.py:133-137 (the message itself is helpful -- 'Download your API key JSON from https://cloud.coinbase.com/access/api' -- but it arrives as a raw traceback because nothing in main() catches it, and .env.example told them this step was optional).

**Recommendation:** Delete the `export COINBASE_API_KEY=...` line from README.md:28. Add an explicit step to the Quick Start: 'Download cdp_api_key.json from https://cloud.coinbase.com/access/api and place it at the repo root -- required even for what-if runs.' Fix .env.example:30's header to say 'required even for what-if runs' instead of 'required for live trading only'.

### [MEDIUM/S] What-if runs silently write into the shared history/ directory; HISTORY_DIR is invisible in --help and README
**Evidence:** historyutil.py:15 and executionledger.py:52 both default `HISTORY_DIR` to `./history/` (the repo's own tracked-but-gitignored-data directory). Nothing in parse_args() (crypto_trading_bot.py:54-298) exposes this as a CLI flag, and running `./venv/bin/python crypto_trading_bot.py --help` confirms it is absent from the flag list and only alluded to by an 'etc.' in the epilog's env-var list. README.md never mentions HISTORY_DIR at all (only the bare `history/` line in the directory-tree diagram, README.md:190, with no explanation). AGENTS.md:12 treats redirecting HISTORY_DIR as a hard rule for agents ('Any bot run you make must ... redirect history'), implying the project itself considers un-redirected writes something to avoid.

**Impact:** A first-time user's very first successful run writes real files into the shared `history/` directory with zero on-screen warning, in a repo whose own contributor norm is that this directory holds per-user data that should stay isolated -- a newcomer has no way to discover the override exists without reading AGENTS.md, a doc framed for AI agents.

**Recommendation:** Add a `--history-dir` CLI flag (mirroring `--notional-usd`'s pattern) that surfaces in --help, or at minimum name `HISTORY_DIR` explicitly (not 'etc.') in the parser epilog and add one line to README's Quick Start recommending `HISTORY_DIR=/tmp/tradbot_scratch` for first-time experimentation.

### [LOW/S] No architecture diagram anywhere in the repo; the only map is prose in a doc framed for AI agents
**Evidence:** `grep -rl 'mermaid|digraph|flowchart' *.md docs/*.md` and `find . -iname '*.png' -o -iname '*.svg' -o -iname '*.drawio'` (excluding venv) both return nothing. The only architecture description is the 'Architecture map' prose section at AGENTS.md:73-78, in a file whose own first line says 'Canonical guidance for ANY AI coding agent ... CLAUDE.md is just a pointer here' -- i.e. framed as agent onboarding, not human-code-reading material, and README.md links to it only as 'Start here for AI-assisted development' (README.md:155).

**Impact:** A human dev trying to build a mental model of the runtime path (main -> marketdata -> panel -> voteschema -> coinbaseutil2 -> historyutil/executionledger) has to reconstruct it by reading ~2600 lines of crypto_trading_bot.py plus several utility modules, or happen to read an agent-oriented doc closely enough to extract the one paragraph that has it.

**Recommendation:** Add a short diagram (ASCII or a mermaid fence, which renders natively in most doc viewers) to README.md near 'What each recommendation is based on', reusing AGENTS.md:75's existing prose map as the source content -- no new research needed, just a visual restatement of what's already written.

### [MEDIUM/S] crypto_trading_bot.py has no module docstring or doc pointers, and main() sits after ~40 helper functions in a 2629-line file, breaking top-down reading
**Evidence:** Lines 1-53 of crypto_trading_bot.py are pure imports with no module-level docstring or comment describing the file's role. `grep -n 'AGENTS.md|OPERATIONS_MANUAL' crypto_trading_bot.py` returns nothing -- the file never points a reader to the docs that explain it. `grep -n '^def |^class ' crypto_trading_bot.py` lists ~40 functions (parse_args, get_trends_status, sendCoinCheckRequest, get_llm_response, resolve_vote, PanelDecision, decision_allows_trade, process_coin_with_comparison, buy_something, maybe_execute_buy, run_llm_preflight, ...) all defined before `main()`, which starts at line 1973 of a 2629-line file and is itself ~656 lines long. AGENTS.md:99 already flags the file's monolithic size as a known wart ('it's one big file ... Splitting it into modules is the standing refactor candidate') -- this finding is the narrower, cheaper fix (docstring + pointer) distinct from that larger standing refactor.

**Impact:** Told to 'open crypto_trading_bot.py and read main() top-down,' a newcomer has to scroll past 1900+ lines of helper functions with no framing context to reach the entry point, then read a 656-line function, then jump backward through the file to see what each helper actually does -- the file's physical order is the reverse of a natural reading order.

**Recommendation:** Add a short module docstring at the top of crypto_trading_bot.py stating the file's role and pointing to AGENTS.md's architecture map and OPERATIONS_MANUAL.md; optionally add a one-line comment above each major function-group boundary (vote parsing, consensus/trade-gate, discovery, main) so a reader can jump via search without needing the full module split.

### [LOW/S] BlobbyTrader (coinbaseutil2.py) is an opaque name for the class that places real-money Coinbase orders
**Evidence:** coinbaseutil2.py:109 defines `class BlobbyTrader:` -- the sole Coinbase REST client wrapper in the file (confirmed via `grep -n '^class ' coinbaseutil2.py`, which shows only OrderResult and BlobbyTrader). There is no comment anywhere explaining the name, and no `coinbaseutil.py` (non-'2') exists (`ls coinbaseutil*` shows only coinbaseutil2.py), so the '2' suffix is also a dangling artifact of some earlier rename. The name is used 25 times across the codebase (`grep -rn 'BlobbyTrader' --include=*.py . | wc -l`).

**Impact:** Someone tracing the money path from `main()` to the actual order-placement call has to already know that 'BlobbyTrader' means 'the Coinbase trader' -- a name search for 'Coinbase' + 'trader' or 'client' won't surface it, adding friction to exactly the code a reviewer most needs to find quickly.

**Recommendation:** Rename the class to something descriptive (e.g. `CoinbaseTrader`) with a thin backward-compatible alias (`BlobbyTrader = CoinbaseTrader`) if minimizing churn across the 25 call sites matters more than a clean rename in one pass.

### [LOW/M] 37 markdown files at repo root, including a 417KB file referenced nowhere, obscure the 'start here' path
**Evidence:** `ls *.md | wc -l` returns 37. Several are full feature-design docs for unimplemented ('Design Only') features (e.g. FLASH_LOAN_FEATURE.md, METEORA_ARBITRAGE_FEATURE.md, STOCK_TRADING_FEATURE.md per README.md's own status table, lines 129-146). `Restore Directional Analysis.md` is 417,216 bytes (`ls -la`) and is not mentioned in README.md or AGENTS.md at all (`grep -n 'Restore Directional' README.md AGENTS.md` returns nothing).

**Impact:** A newcomer's very first `ls` on the repo shows nearly 40 similarly-named, similarly-styled markdown files with no visual distinction between 'this is the core bot, read this' and 'this is a speculative design doc for a feature that doesn't exist yet,' and at least one large file that isn't indexed anywhere and gives no hint of its purpose from its filename alone.

**Recommendation:** Move the design-only / feature-specific docs (everything the README's own tables mark Design Only, plus one-off files like the untitled 417KB doc) into a `docs/design/` or `docs/features/` subdirectory, leaving only README.md, AGENTS.md, CLAUDE.md, OPERATIONS_MANUAL.md, and MODELS.md at root for the core bot.
