# Documentation (enablement for AI agents + human newcomers; staleness; repetition)

## Summary
The documentation has a genuinely excellent core: AGENTS.md is a dense, accurate, single-entry guide for any AI agent, CLAUDE.md correctly defers to it, MODELS.md is current and empirically verified, OPERATIONS_MANUAL.md matches the current CLI, and the docs/ subfolder practices exemplary hygiene (historical records explicitly stamped as superseded with executed addenda). The problem is the root: 37 markdown files totaling 1.5 MB with no separation of current-reference from design-only-never-implemented, historical plans, and a 407 KB raw IDE chat transcript — so an agent or newcomer cannot tell authoritative docs from aspirational or dead ones by looking at the tree. Concrete staleness also exists in two docs the README itself links as authoritative: CRYPTO_TRADING_BOT.md (the "core design doc") predates the entire money-path safety model, and the README Quick Start references a Coinbase env var that does not exist in the code. The excellent docs (AGENTS/MODELS/OPERATIONS) largely mitigate this for a careful reader, but the failure modes land on exactly the safety-critical onboarding path.

## Strengths
- AGENTS.md is the clear single source of truth and is genuinely high-quality: hard rules, environment gotchas, architecture map, and empirically-verified API quirks all in one dense but readable page (~112 lines). README.md:155 and CLAUDE.md both point to it as 'start here', so the ONE true entry doc is discoverable.
- MODELS.md is current and rigorous: registry table with per-model verification dates (MODELS.md:15-27), migration history, and live-captured request/response shapes per provider (Appendix, MODELS.md:71-273). It correctly names modelregistry.py as the single source of truth and matches the code.
- README.md's Projects/Feature tables (README.md:121-147) correctly classify each feature as Implemented vs Design Only, and I verified this holds against code: polymarketutil.py/lp_arbitrage.py/dex/ exist and are wired in, while flash-loan/meteora/stock/whale/correlated-pair/compare-with-bitcoin have zero code — the status legend is honest.
- The docs/ subfolder is a model of hygiene: SESSION_HANDOFF_2026-07-18.md:3-10 is explicitly stamped 'now a historical record' with an EXECUTED/ADDENDUM banner, and reflections-2026-07-18/ is well-organized — this is exactly what the root is missing.
- .env.example is accurate and current (correct key names, documents cdp_api_key.json via COINBASE_CREDENTIALS_FILE, model-override vars match MODELS.md) — it is a better onboarding artifact than the README Quick Start.

## Findings

### [HIGH/M] CRYPTO_TRADING_BOT.md — the README-linked 'core design doc' — is substantially superseded and omits the entire money-path safety model
**Evidence:** README.md:123 links CRYPTO_TRADING_BOT.md as the design doc for the core system with a ✅ Implemented badge, and README.md:228 tells 'I want to trade crypto with AI recommendations' newcomers to start there. But the doc predates the current safety architecture: `grep` for LIVE_TRADING_CONFIRMED/--live/whatif/marketdata/notional in CRYPTO_TRADING_BOT.md returns nothing — it describes none of the double-lock live interlock, whatif default, spend caps, fail-closed consensus, or the marketdata block. It is also concretely stale: line 7 says 'OpenAI GPT-4o' (registry is gpt-5.5 per MODELS.md:19), line 19 lists 'Python 3.9+' as a prerequisite which directly contradicts AGENTS.md:20 ('system python3 (3.9) lacks every dependency and will fail'), and line 1 begins with a stray-typo header `pl# Crypto Trading Bot`.

**Impact:** A newcomer or agent following the README's own 'start here' pointer for the real-money core system learns an obsolete model of the bot and, critically, nothing about the money-path safety model (double lock, caps, fail-closed) that is the single most important thing to understand before touching this repo. The 'Python 3.9+' line will actively send them down a broken-environment path.

**Recommendation:** Either (a) rewrite CRYPTO_TRADING_BOT.md's Features/Quick Start to reflect current behavior (double-lock live interlock, whatif default, --notional-usd/--run-spend-cap-usd/--daily-spend-cap-usd caps, fail-closed consensus, marketdata.py block, gpt-5.5, venv 3.11) and fix the `pl` typo on line 1, OR (b) demote it: move it to docs/design/, add a 'superseded by AGENTS.md + OPERATIONS_MANUAL.md for current behavior' banner at top, and change README.md:123/228 to point at AGENTS.md/OPERATIONS_MANUAL.md as the authoritative current references.

### [HIGH/S] README Quick Start tells users to set COINBASE_API_KEY, an env var that does not exist in the code, and never mentions the required cdp_api_key.json
**Evidence:** README.md:28 Quick Start says `export COINBASE_API_KEY=...   # Coinbase trading`. `grep -rn COINBASE_API_KEY` across all *.py returns zero matches — no code reads it. The real Coinbase credential is a JSON file, documented correctly everywhere else: OPERATIONS_MANUAL.md:181/312-324 (cdp_api_key.json via COINBASE_CREDENTIALS_FILE), .env.example:30-32, and AGENTS.md:21. The README Quick Start block (lines 26-32) never mentions cdp_api_key.json at all. README.md:26-28 also uses GOOGLE_API_KEY/CLAUDE_API_KEY which ARE correct (verified in llm_utils/gemini_client.py:19 and claudeutil.py:27), which makes the one wrong line more likely to be trusted.

**Impact:** A newcomer following the top-of-README Quick Start for this real-money bot sets a no-op env var, omits the actually-required credentials file, and cannot construct the Coinbase client (which AGENTS.md:21 notes is built even in what-if mode). README is the human entry doc; it is flatly wrong on the money credential and contradicts three other in-repo sources.

**Recommendation:** In README.md:26-32, delete the `export COINBASE_API_KEY=...` line and replace with an instruction to place cdp_api_key.json at repo root (or set COINBASE_CREDENTIALS_FILE), matching OPERATIONS_MANUAL.md:312-324 and .env.example:30-32. Optionally just point the Quick Start at 'copy .env.example to .env' since that file is already correct.

### [MEDIUM/M] Root documentation sprawl: 37 files / 1.5 MB with no folder separation of current-reference vs design-only vs archive
**Evidence:** `ls *.md` = 37 files, 1.5 MB total. Six are design-only-never-implemented per README's own status column (FLASH_LOAN_FEATURE.md, METEORA_ARBITRAGE_FEATURE.md, STOCK_TRADING_FEATURE.md, WHALE_ALERT_INTEGRATION_FEATURE.md, CORRELATED_PAIR_FEATURE.md, COMPARE_WITH_BITCOIN_FEATURE.md) totaling 233 KB, verified to have zero backing code. Others are historical plans (LIVE_MODE_PREFLIGHT_IMPLEMENTATION_PLAN.md, EVALUATION_LESSONS_LEARNED_2026-07-18.md, INSTRUCTIONS_FOR_IMPLEMENTATION.md dated 2026-04) sitting flat alongside the 4 genuinely-current references (README/AGENTS/MODELS/OPERATIONS_MANUAL). The tree gives no signal about which is which; only README's tables encode status. Contrast docs/ which is cleanly organized. Per-file disposition (representative): keep-root = README, AGENTS, MODELS, OPERATIONS_MANUAL, CLAUDE; move-docs/design = *_FEATURE.md design-only + CRYPTO_TRADING_BOT.md + GENERAL_PURPOSE_LLM_COMPARE...; archive = EVALUATION_LESSONS_LEARNED, LIVE_MODE_PREFLIGHT_IMPLEMENTATION_PLAN, INSTRUCTIONS_FOR_IMPLEMENTATION, LLMCompareFeature; delete-candidate = 'Restore Directional Analysis.md'.

**Impact:** An AI agent or newcomer cannot distinguish authoritative from aspirational or dead docs by the file tree, and a naive 'read the *.md files' load pulls in 233 KB of unbuilt-feature specs and historical transcripts. Increases the chance an agent implements against a design-only doc believing it reflects current code.

**Recommendation:** Create docs/design/ (design-only feature specs), docs/archive/ (historical plans/evals/superseded design docs), and move the classified files there; keep only README/AGENTS/MODELS/OPERATIONS_MANUAL/CLAUDE at root. Update README's Design Doc links to the new paths. Add one line to AGENTS.md's 'Reference docs' (AGENTS.md:78) stating docs/design = not-yet-built, docs/archive = historical.

### [MEDIUM/M] llm_compare.py is documented four times over, and LLMCompareFeature.md is stale (retired model, obsolete 2-LLM framing)
**Evidence:** Four root docs cover the same tool: README_LLM_COMPARE.md (user quick start), LLM_COMPARE_OPERATIONS_MANUAL.md (ops manual), LLMCompareFeature.md (design doc), and GENERAL_PURPOSE_LLM_COMPARE_AND_INTEGRATE_FEATURE.md (abstracted design, 38 KB) — the first two duplicate the third/fourth's now-shipped design. LLMCompareFeature.md is concretely stale: line 30 and line 113 hardcode the retired model `claude-sonnet-4-20250514` (MODELS.md:48 documents this exact ID as retired→404), and lines 9/432 describe an obsolete 'Send identical prompts to both Gemini and Claude' 2-LLM design though the system now runs 5 providers (README_LLM_COMPARE.md:1 and LLM_COMPARE_OPERATIONS_MANUAL.md:25 both list all five).

**Impact:** Four overlapping docs for one standalone tool is a maintenance liability (each model/flag change must be reconciled in four places, and clearly wasn't — the design docs rotted). An agent reading LLMCompareFeature.md would resurrect a dead model ID.

**Recommendation:** Keep README_LLM_COMPARE.md (quick start) + LLM_COMPARE_OPERATIONS_MANUAL.md (reference) as the two live docs; move LLMCompareFeature.md and GENERAL_PURPOSE_LLM_COMPARE_AND_INTEGRATE_FEATURE.md to docs/design/ with a 'superseded — see README_LLM_COMPARE.md' banner. If either is kept, delete the hardcoded claude-sonnet-4-20250514 references (LLMCompareFeature.md:30,113) and replace model mentions with a pointer to modelregistry.py/MODELS.md.

### [INFO/S] AGENTS.md is at the healthy upper bound of a single dense page; its two long bullet-lists are the growth risk and partially duplicate MODELS.md
**Evidence:** AGENTS.md is 19 KB / 112 lines — still skimmable, but 'Known API gotchas' (AGENTS.md:80-94, 14 dense bullets) and 'Process lessons' (AGENTS.md:96-111, 12 bullets) are where future growth will land. Several provider gotchas restate content covered in more depth in MODELS.md (e.g. AGENTS.md:89-92 on gpt-5.x max_completion_tokens / Gemini reasoning-token emptiness / Perplexity truncation vs MODELS.md:113-129, 146-159, 263-267 and Appendix 2). This is currently acceptable index-vs-detail overlap, not contradiction.

**Impact:** No problem today, but the two bullet-lists are the section most likely to push AGENTS.md past the point where agents skim rather than read, and duplicated provider quirks risk diverging from MODELS.md over time.

**Recommendation:** Leave as-is for now, but when either bullet-list next grows, split the empirical API-quirk bullets into a linked docs/API_GOTCHAS.md and keep AGENTS.md's version to one-line pointers into MODELS.md/that file. Treat MODELS.md as the canonical home for per-provider request/response quirks and have AGENTS.md reference rather than restate them.
