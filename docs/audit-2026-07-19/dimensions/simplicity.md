# Simplicity & MVP scope discipline

## Summary
The money path itself is admirably small and well-factored (~10.9k lines, 616 tests, seam-injected data pipeline), but it is embedded in a repo where satellites outweigh the product: 20.6k of 31.5k non-test Python lines (65% more code than the core) belong to experiments untouched by feature work since May/June 2026 with essentially zero pytest coverage, and 38k lines of markdown of which ~16k are design docs for never-built features plus one 417KB pasted AI-chat transcript. Two of those satellites (leading_indicator_tester.py, lp_arbitrage.py) are independent real-money live-trading entry points that lack the main bot's double-lock interlock, so the sprawl is not merely inert weight. The highest-leverage cuts are cheap: archive the correlation/DEX universe (one small class extraction required), quarantine the doc attic, and collapse the 20-site prompt duplication that makes every money-path prompt edit a 5-file change.

## Strengths
- The core money path is genuinely MVP-sized and clean: crypto_trading_bot.py (2,629) + coinbaseutil2.py (603) + marketdata.py (863) + voteschema.py (388) + executionledger.py (367) + historyutil.py (289) with 616 tests concentrated exactly there (tests/test_consensus.py 981 lines specs the fail-closed gate); the market-data pipeline was injected at a seam with zero changes to consensus code, exactly as AGENTS.md:104 prescribes.
- Recent hygiene is active, not aspirational: commit a2edfc2 (2026-07-19) deleted 2,699 lines of dead code (--use-fib junk file, output6,tmp, coinbaseutil2nokey.py) and untracked per-user data; lab/ is a correctly-used quarantine directory (lab/jlp_*_lab.py, lab/session_tests_20260718/ evidence logs).
- README.md:121-147 honestly labels feature status (✅ Implemented vs 📋 Design Only) and AGENTS.md:76 explicitly documents the llm_compare parallel-stack wart, so the sprawl is at least mapped, not hidden.
- Dependency fragmentation is deliberate and beneficial: requirements.txt keeps the core install free of satellite deps (statsmodels, solders, httpx live only in requirements_correlation_tracker.txt / requirements_dex.txt).
- The learning loop the owner values (tradeanalyzer.py 1,032 lines + history/recorder.py + whatif cadence runbook) is properly integrated and tested (tests/test_analyzer.py 602 lines, tests/test_history_integrity.py 387 lines) — correctly treated as core.

## Findings

### [HIGH/S] Satellite tools are independent live-money entry points without the bot's double-lock interlock
**Evidence:** leading_indicator_tester.py:4827-4830 accepts `--trading-mode ... live (real swaps)`; its only gate is its own preflight (leading_indicator_tester.py:5397-5426 — pass/fail on pair viability, no LIVE_TRADING_CONFIRMED check) before "# LIVE MODE: Execute real Jupiter swap" (leading_indicator_tester.py:4005). lp_arbitrage.py:20 documents `--trading-mode=live  # Real execution` and lp_arbitrage.py:1283-1328/1402-1405 executes live with only a wallet-key check. Contrast the main bot, where live requires --live AND LIVE_TRADING_CONFIRMED=1 (crypto_trading_bot.py:70-93, resolve_trading_mode at 1414). Neither satellite writes to executionledger or respects the daily/run spend caps (executionledger imported only by crypto_trading_bot.py, tests, and scripts/reconcile_positions.py — verified by import grep).

**Impact:** The repo's hard-won fail-closed/interlock posture exists only in crypto_trading_bot.py; ~7k lines of unmaintained satellite code can place real Jupiter swaps from a user's wallet with weaker gates, no ledger, and no caps. This converts "dead weight" into standing risk and is the single strongest argument that the satellite surface is not harmless to keep.

**Recommendation:** Preferred: archive these tools (see the archive-plan finding). If the owner wants to keep them runnable, add a stopgap: in leading_indicator_tester.py main() and lp_arbitrage.py main(), refuse trading_mode=='live' unless os.environ.get('LIVE_TRADING_CONFIRMED')=='1', printing the same downgrade notice the bot uses (mirror resolve_trading_mode's message in crypto_trading_bot.py:1414-1462). This is a ~15-line change per file and needs no other refactoring.

### [HIGH/M] The correlation/leading-indicator universe (~10.6k lines, ~34% of non-test Python) is dormant, untested, and unused by any documented workflow
**Evidence:** leading_indicator_tester.py (5,644 lines), correlation_tracker.py (2,900), preflight.py (504), test_trustwallet_swap.py (1,077), test_jupiter_swap.py (462): last feature-work commits are 2026-05/06 (git log: correlation_tracker.py 2026-06-05, dex/trustwallet.py 2026-05-21, test_jupiter_swap.py 2026-05-14; leading_indicator_tester.py's 2026-07-19 touch was dead-code removal only, per a2edfc2's message). Zero pytest coverage except one class: tests/test_fibonacci_analyzer.py:37 imports FibTradeFilter from leading_indicator_tester (TestFibTradeFilter at line 603). The documented workflows never invoke them (docs/RUNBOOK_whatif_cadence.md:38-41 and docs/RUNBOOK_live_acceptance.md:41-45 both run crypto_trading_bot.py with fixed --coins). Money-path coupling is one-way and thin: preflight.py imports correlation_tracker, so every pytest run transitively imports ~9k satellite lines via the FibTradeFilter import.

**Impact:** Half the repo's Python is code no runbook uses and no test protects, yet agents must read past it (and the suite imports it) on every session; it also carries the unguarded live path from the previous finding.

**Recommendation:** Archive plan: (1) move class FibTradeFilter + FibFilterResult (leading_indicator_tester.py:1024-~1200) into fibonacci_analyzer.py (its only dependency is FibonacciReport from that module) and update tests/test_fibonacci_analyzer.py:37; (2) git rm leading_indicator_tester.py, correlation_tracker.py, preflight.py, test_trustwallet_swap.py, test_jupiter_swap.py, correlation_tracker_config.yaml, requirements_correlation_tracker.txt, tests/test_correlation_data/, tests/test_multi_pair_data/, tests/generate_test_data.py, tests/generate_multi_pair_test.py (git history preserves everything; optionally tag `archive/correlation-universe` first); (3) remove the candidate-export hooks (see separate finding). Owner sign-off required since README advertises these as implemented.

### [HIGH/M] Core analysis prompts exist in 20 copies across 5 files; provider clients are duplicated across two stacks
**Evidence:** grep counts 4 copies of the load-bearing prompt "sophisticated trading bot designed for short-term appreciation" in each of claudeutil.py, openaiutil.py, grokutil.py, perplexityutil.py, and crypto_trading_bot.py (Gemini inline, lines 510-643) — 20 sites; the discovery prompt has 8 copies. Each provider util is the same 5-method class differing only in SDK call + structured-output config (claudeutil.py:36-191 is the template; openaiutil/grokutil/perplexityutil repeat it). Meanwhile llm_utils/ contains a second, properly-abstracted implementation of the same 5 providers (llm_utils/base.py LLMClient ABC + 5 clients, 526 lines) used only by llm_compare.py — the two-stack wart AGENTS.md:76 documents. The 20-copy duplication inside the money path itself is NOT documented.

**Impact:** Every prompt-wording change on the money path is a 5-file, up-to-20-site edit — the highest-frequency class of change in an LLM trading bot — and drift between copies is a live risk (the dex_mode discovery prompts already diverge per provider). Registry migration already had to touch both stacks (llm_utils clients modified 2026-07-18).

**Recommendation:** Cheapest consolidation, no architecture change: create panelprompts.py with the 4 prompt-builder functions (coin_check, trend_check, integrated_coin, integrated_trend), each taking (coin_symbol, coin_type, market_block, trends_data, peer_analysis) and returning the final string — all 5 call sites (4 utils + Gemini inline) call them, keeping their own SDK plumbing. That reduces 20 prompt sites to 4 with ~zero behavioral risk and is separately testable. Deleting the llm_utils/ second stack rides with the llm_compare finding below; do not attempt a full provider-adapter unification in the same change.

### [MEDIUM/S] Bare `pytest` at repo root collects live-API probe scripts and colliding module names
**Evidence:** No pytest.ini/pyproject.toml/setup.cfg/tox.ini exists (verified by ls), so pytest run without args uses rootdir collection. test_coinbase.py:2-21 executes at module import: reads cdp_api_key.json and calls client.get_accounts() — a real authenticated Coinbase call at collection time, outside tests/conftest.py's network guard (which only governs tests/). test_jupiter_swap.py and test_trustwallet_swap.py (module-level dex imports) and lab/session_tests_20260718/test_consensus.py / test_extract_rec.py also get collected; tests/test_consensus.py and lab/session_tests_20260718/test_consensus.py share a basename with no __init__.py in either dir (verified), producing an import-file-mismatch error.

**Impact:** The single most habitual command an AI agent runs (`pytest`) either errors confusingly or silently makes a credentialed exchange API call — read-only, but it defeats the repo's carefully built no-network-in-tests posture and wastes every new agent's time rediscovering that only `pytest tests/` works.

**Recommendation:** Add a 3-line pytest.ini at repo root: `[pytest]` / `testpaths = tests` / `norecursedirs = lab venv`. Additionally rename the root probe scripts so they can never be collected: test_coinbase.py -> probe_coinbase_auth.py, test_jupiter_swap.py -> probe_jupiter_swap.py, test_trustwallet_swap.py -> probe_trustwallet_swap.py (they are interactive programs, not tests), updating the two references in docs if any.

### [MEDIUM/M] --dex is a second, less-hardened exchange backend living inside the money path
**Evidence:** crypto_trading_bot.py:2245-2262 constructs SolanaDEXTrader on --dex; the live DEX fill path (crypto_trading_bot.py:1578-1595) maps the trader's result dict straight to a ledger fill row — no fill-confirmation follow-up equivalent to the CEX path's structured result (lines 1596-1609, backed by coinbaseutil2's get_order confirmation). dex_mode also threads through every panelist's discovery method (claudeutil.py:36-39 and same in openaiutil/grokutil/perplexityutil) with a separate Solana-meme-coin prompt variant. It does share the live double-lock (WHATIF_MODE resolved once at crypto_trading_bot.py:1414). Neither runbook ever passes --dex (docs/RUNBOOK_whatif_cadence.md:38-41, docs/RUNBOOK_live_acceptance.md:41-45).

**Impact:** The hardening investment (fill confirmation, duplicate-order dedupe, fee auditing per AGENTS.md gotchas) applies only to the CEX branch, so the bot's most-audited code path has a sibling branch that silently gets none of it; every money-path change must now be reasoned about twice, and the dex_mode parameter is 20% of each provider util's discovery surface.

**Recommendation:** Owner decision: if DEX trading is not part of the current live experiment (runbooks say it is not), remove --dex/--slippage/--test-wallet and the DEX branches from crypto_trading_bot.py (lines 215-237, 1578-1595, 2245-2262, 299-2146) and the dex_mode parameter from the four provider utils, leaving dex/ importable for the satellites until they are archived. If it must stay, add a hard refusal: `--dex` with live mode exits with "DEX live is not fill-confirmation hardened" until it gets the CEX treatment.
