# Testing infrastructure (as it enables AI-assisted development)

## Summary
The `tests/` suite is genuinely good for an AI-maintained MVP: 616 tests pass deterministically in ~2.85s, a socket-level network guard fails loud and names the offending test, fixtures are real captured API shapes with provenance metadata, and the pure decision/cap/parse/order primitives are each well unit-tested. Two structural gaps undercut the "one command you can trust" property, though: (1) the single most natural command, bare `pytest`, is NOT what the suite is scoped to — there is no pytest config, so it collects unguarded root-level `test_*.py` probe scripts that make a live Coinbase call at collection and expose real-swap functions; and (2) the actual end-to-end buy path (`maybe_execute_buy` + the gate wiring in `main()`) has zero coverage even though every leaf it calls is tested, so an agent can refactor the money path and keep all 616 tests green. These are the regression traps an AI agent is most likely to hit silently.

## Strengths
- Suite is fast, deterministic, and green: `./venv/bin/python -m pytest tests/ -q` -> 616 passed in 2.85s, with zero xfail/skip in the money-path files (the historical xfails were cleared by T8; see tests/test_extract_recommendation.py:61 and tests/test_consensus.py:226).
- Network guard is well-engineered: tests/conftest.py:90-93 patches at the socket layer (connect/connect_ex/create_connection/getaddrinfo) so it catches ANY library's real call, is function-scoped so it can't leak between tests, fails loudly with the offending nodeid (conftest.py:68-78), and provides a documented `@pytest.mark.allow_network` escape hatch (conftest.py:47-54).
- Fixtures are real captured API shapes, not hand-written, and carry provenance: tests/fixtures/coinbase/duplicate_rejection.json has `_captured`/`_finding`/`_original_fill` keys, and tests/fixtures/structured_output/*.json are loaded and asserted against in tests/test_structured_requests.py:21-84.
- Time is injected where correctness depends on it, avoiding flakiness and the documented stdlib-monkeypatch trap: executionledger cap functions take a `now=` param (tests/test_execution_ledger.py:472-489), and tests/test_market_block_cache.py:82-88 uses a controllable FakeClock while explicitly warning against patching the real `time` module.
- The trade GATE as a pure predicate is thoroughly spec'd: bot.decision_allows_trade (23 refs) and the block_reason vocabulary are exercised across many fail-closed cases in tests/test_consensus.py (sub_quorum, parse_failure, symbol_mismatch, tiebreaker_unavailable, client_init_failure).
- The order/fill layer is driven against fixtures with a FakeClient (tests/test_execution_ledger.py:138-362), covering create-success, filled/open/cancelled follow-ups, generic failure, and raise-on-create paths without touching credentials or network.

## Findings

### [HIGH/S] Bare `pytest` collects unguarded root-level probe scripts that make a live Coinbase call at collection and expose real-swap functions
**Evidence:** There is NO pytest config in the repo (ls confirms no pytest.ini/setup.cfg/tox.ini/pyproject.toml and no root conftest.py), so `testpaths` is unset and bare `pytest` collects from rootdir. Three root-level `test_*.py` probe scripts then get collected: (a) test_coinbase.py:18-20 runs `client = RESTClient(...)` then `client.get_accounts()` at MODULE TOP LEVEL, i.e. during pytest collection/import, an unconditional live Coinbase call using the real cdp_api_key.json present at repo root; (b) test_trustwallet_swap.py:267 `def test_with_private_key()` and :593 `def test_sell_with_private_key()` match pytest's collectible `test_*` name pattern and drive a real ~$1 DEX swap flow — with SOLANA_PRIVATE_KEY set (test_trustwallet_swap.py:279-285) they proceed automatically; otherwise they block on getpass. The tests/conftest.py network guard does NOT protect any of these because it is scoped to the tests/ subtree (no root conftest.py). AGENTS.md always instructs `pytest tests/`, but nothing enforces the scoping. Separately, even `pytest tests/` imports tests/generate_multi_pair_test.py because it matches the default `*_test.py` glob (it is a data generator, not a test).

**Impact:** The repo's entire testing value proposition for AI agents — 'network-blocked, fast, trustworthy, one command' — is silently broken by the most natural command an agent or human types. Bare `pytest` makes a live authenticated exchange call at collection time (money-path adjacent, uses real per-user creds) and can auto-execute a real on-chain swap when a wallet key is in the environment, entirely outside the network guard.

**Recommendation:** Add a pytest.ini (or [tool.pytest.ini_options] in a new pyproject.toml) with `testpaths = tests`, `python_files = test_*.py`, and consider `--import-mode=importlib`, so collection is confined to the guarded suite regardless of invocation. Additionally rename the three root probe scripts out of the `test_*.py` namespace (e.g. probe_coinbase.py, probe_jupiter_swap.py, probe_trustwallet_swap.py) or move them under a non-collected dir like scripts/probes/, and rename tests/generate_multi_pair_test.py so it does not match `*_test.py`. Update the AGENTS.md 'Verify' snippet to note that config now makes bare `pytest` safe.

### [HIGH/M] End-to-end buy path (`maybe_execute_buy` + the duplicated gate wiring in `main()`) has zero test coverage although every primitive it calls is tested
**Evidence:** crypto_trading_bot.py:1620 `maybe_execute_buy` contains real money-path branching — daily LIVE cap check (1639-1644), per-run SpendTracker cap (1647-1651), exclude-list short-circuit (1654-1658), and dispatch to buy_something (1660) plus whatif_buys tally (1661-1662) — but it is referenced by zero tests (grep of tests/ for maybe_execute_buy/buy_something returns nothing). No test invokes main(): tests/test_framing.py:243 states its flow test runs 'without invoking bot.main()', and tests/test_model_registry.py documents a 'no-main() convention'. The gate->execute wiring `if decision_allows_trade(...) and 'BUY' in final_action: maybe_execute_buy(coin_symbol)` is duplicated verbatim at crypto_trading_bot.py:2450-2451 (direct mode) and 2584-2585 (hybrid discovery mode), both inside the untested main() loop. The leaf functions ARE covered (decision_allows_trade in test_consensus, SpendTracker.try_spend in test_safe_defaults.py:164-200, daily_cap_would_exceed in test_execution_ledger.py:472-489, BlobbyTrader via FakeClient), so the gap is precisely the assembly of them into the actual buy action.

**Impact:** An AI agent editing the money path keeps all 616 tests green while breaking it: reordering the two cap checks, moving coinsToBuy.append before the caps, dropping the exclude-list branch, or altering only one of the two identical main() call sites (so one loop trades under weaker conditions) are all invisible to the suite. This is the highest-consequence silent-regression class for this repo.

**Recommendation:** Extract the duplicated conditional at crypto_trading_bot.py:2450-2451 and 2584-2585 into one helper (e.g. `gate_and_maybe_buy(decision, final_action)`) so both loops share a single tested path. Add a focused test that monkeypatches the module globals (WHATIF_MODE, NOTIONAL_USD, DAILY_SPEND_CAP_USD, spend_tracker, coinsToExclude, coinsToBuy) and stubs buy_something/executionledger.daily_cap_would_exceed, asserting: a daily-cap refusal and a per-run-cap refusal each place no order and commit no ledger rows; an excluded coin in live mode places no order but still appends to coinsToBuy; and an approved buy calls buy_something exactly once and increments whatif_buys only in what-if mode.

### [MEDIUM/S] Load-bearing 'import is side-effect-free' invariant is unpinned, and the network guard is blind at collection/import time
**Evidence:** AGENTS.md (Environment) declares `import crypto_trading_bot` must be side-effect-free (no argv/network/client construction) and that 'tests depend on it', but no test asserts this — grep of tests/ finds no subprocess/importlib import-purity check (the only capsys tests, test_model_registry.py:489-533, cover run_llm_preflight, not import). Structurally, the guard cannot catch an import-time regression: tests/conftest.py:81-93 is a function-scoped autouse fixture, so its socket patches are installed per-test, whereas `import crypto_trading_bot as bot` executes during collection, before any fixture runs. A regression adding module-level network/env code to the bot would therefore pass the guard on any online developer machine (it only fails loudly if the CI host happens to be offline, as a collection error).

**Impact:** The most likely way an AI agent breaks the repo's testability invariant — adding module-level env lookup, network call, or client construction to the large single-file bot — is not deterministically caught, only incidentally caught when the host is offline. Coverage appears to protect the invariant but does not.

**Recommendation:** Add a dedicated test that imports crypto_trading_bot in a clean subprocess (subprocess.run with sockets blocked via a sitecustomize or an env flag, and no extra argv) and asserts the import produces no stdout/stderr and makes no network/client-construction call. This pins the AGENTS.md invariant deterministically regardless of host connectivity and documents it as an executable spec.

### [INFO/S] block_reason vocabulary has no single source of truth (spec'd only by scattered string assertions in tests) — already-documented
**Evidence:** The block_reason strings the bot emits are asserted as bare literals across tests/test_consensus.py (e.g. 'sub_quorum' at :255/:318, 'parse_failure' at :319-320/:365/:408, 'symbol_mismatch' at :623/:660, 'tiebreaker_unavailable' at :283/:445, 'client_init_failure' at :751-891, plus composed forms like block_reason == 'sub_quorum: only 1 of 2 panelist(s) produced a vote' at :828). There is no enum/frozenset/doc defining the vocabulary; AGENTS.md:109 explicitly documents this as intentional ('there is no separate enum/doc; read the test assertions').

**Impact:** Low-consequence for this MVP because block_reason is display/logging only and is never traded on (resolve_structured_vote returns just vote.action), so a drifted string cannot change a money decision. The cost is discoverability/maintainability: a typo'd reason emitted by the bot is only caught if a test happens to assert that exact path, and an agent must read the whole test file to learn the vocabulary.

**Recommendation:** Optional (not required for correctness): define the reason prefixes once as a module-level frozenset/enum in crypto_trading_bot.py (or a small reasons.py) and reference it from both the emit sites and the test assertions, making the vocabulary discoverable and typo-proof without changing behavior. Keep the composed message text free-form. Label any tracking of this as already-documented per AGENTS.md:109.
