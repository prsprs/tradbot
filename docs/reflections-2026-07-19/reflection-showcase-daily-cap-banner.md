The single most useful move this session was reading `maybe_execute_buy` *before* writing anything. It told me exactly which function the live cap gate consults (`executionledger.live_spend_today()`) and, critically, that the live path and the whatif path use different tallies (`live_spend_today()` vs `spend_today(trading_mode='whatif')`). Without that I'd have guessed wrong about which spend to show in the banner. The task's own demo (seed a *live* intent, run in *whatif*, expect it to render) was the tiebreaker that confirmed the banner must always show LIVE spend regardless of run mode. Read that demo spec carefully — it encodes a decision, not just a smoke test.

The locking rules sounded scarier than they were. AGENTS.md warns the ledger lock and recommendations lock must never be co-held, so I braced for having to reason about lock ordering. In reality `load_executions()` (and thus `live_spend_today()`) is lock-free — it just reads the file — and the existing run-start `[LEDGER] daily snapshot` already reads the ledger the same way at startup. So "hook in without changing lock ordering" meant "don't take a lock at all." Verify whether the function you're reusing actually acquires a lock before assuming you're near the danger.

macOS has no `timeout`/`gtimeout`. My `timeout 60 ...` gave a silent exit 127 that I first misread as a bot failure. The clean workaround: run the bot with `run_in_background: true`, poll the output file for the banner line (which prints before analysis), then `pkill`. Don't reach for `timeout` here.

Config-source convention gotcha: the two neighboring lines (`Notional per buy`, `Run spend cap`) have NO `[source]` suffix, but most other startup-banner lines do, and the task wanted one. `get_config_source` returns strings like `DAILY_SPEND_CAP_USD env` (not just the name), so the rendered suffix is `[DAILY_SPEND_CAP_USD env]`. Match that exact shape in test assertions.

Tests: no test drives the full `main()` banner, and `main()` is a ~340-line monster. Extracting a tiny module-level `format_daily_cap_banner_line(cap, source)` made it trivially testable and kept `main()` readable — this matches the repo's existing pattern (see `test_trade_gate.py`, which pins module-level helpers precisely because inline-in-main logic was untestable). Reuse the `scratch_ledger` fixture (monkeypatch `led.EXECUTIONS_FILE` to a tmp file); never let a test touch `./history/`.
